Operational Runbook: Aurionpro User 
Migration & Status Update 
1. Document Overview 
This runbook provides step-by-step operational instructions for executing the  Migration 
processes into the Aurionpro system. It is designed for Business Unit (BU) operators and IT 
administrators to ensure safe, repeatable, and traceable data loads.

6. SSO Error Remediation Workflow 
If an _Error.csv file is generated in the Destination folder, follow this standard operating 
procedure to rectify the data. 
1. Download & Analyze: Download User_Migration_Batch_{Sequence}_Error.csv. Scroll 
to the far right columns to read the ErrorCode and ErrorDescription. 
2. Consult Error Dictionary: 
 
Error Code Meaning Action Required 
ERR_001 Missing 
Mandatory 
Field 
Fill in the missing data (e.g., loginid) in the 
affected rows. 
ERR_003 Invalid Status / 
Type 
Correct isCorpUser or accountStatus 
values to match acceptable system 
inputs. 
ERR_004 Duplicate Login 
ID 
Change the loginid to a unique value; the 
user already exists. 
ERR_006 Invalid Date 
Format 
Fix dates to ensure they strictly follow 
dd/mm/yy. 
 
3. Rectify Data: Correct the errors directly within the CSV file. Remove the ErrorCode 
and ErrorDescription columns once fixed. 
4. Rename & Re-upload: Save the file with the next available sequence number (e.g., if 
Batch 00004 failed, save the corrected file as Batch 00005). Upload it to the Source 
folder and re-run the process.

10. Troubleshooting FAQ 
Q: I dropped the file in the Source folder, but nothing is happening. 
● Action: Check the migration_tracker.csv. If the sequence number of your file is already 
logged as executed, the script is ignoring it. Rename your file to the next available 
sequence. 
Q: All users failed with ERR_006 (Invalid Date Format). 
● Action: Check your Excel/CSV export settings. Excel often auto-formats dates. Ensure 
the raw text data is strictly dd/mm/yy before saving. 
Q: The status update script says "User Not Found". 
● Action: Verify that you are using the system-generated UUID from the _Success.csv file, 
not the loginid or cifnumber. 
Q: The script crashed and no logs were generated. 
● Action: Verify folder permissions. The system account running the Python script must 
have Write access to the Logs and Destination directories. Check the primary system 
event viewer or Cron logs for permission denied errors.
